# RailOps + Gemma 4: Autonomous Reasoning & Human-in-the-Loop Dispatching for Indian Railways

An intelligent, safety-critical railway dispatch orchestration and dynamic forecast platform powered by **Google Gemma 4** (`gemma-4-31b-it` and `gemma-4-26b-a4b-it`) paired with physical simulation and machine learning engines for the **Smart India Hackathon** (Problem SIH26028, Ministry of Railways) and the **Build with Gemma 4 Hackathon**.

## 🧠 Core Engineering Principle: Deterministic Simulation Grounding

> **"Gemma reasons, selects tools, and explains. The engines compute. Gemma never invents a number."**

Every delay figure, conflict score, platform headway, and passenger-minute calculation is generated by deterministic physical simulators (`SimulationOrchestrator`, `CounterfactualSimulator`, `CorridorConflictEngine`) and verified by **`NumberValidator`** (Phase 5). If an ungrounded number is detected, the recommendation is rejected and retried.

## 🛠️ The 12 Agent Simulation Tools

All tools are wrapped with strict Google GenAI JSON schemas and type validation in [`backend/app/agent/tools.py`](backend/app/agent/tools.py):

1. **`get_active_alerts()`**: Current CUSUM speed-drop and corridor junction conflict alerts.
2. **`get_train_state(train_id)`**: Real-time position, current delay, next stations, and P10/P50/P90 ETA quantiles.
3. **`query_conflicts(junction_id)`**: Junction bottleneck score and converging train details.
4. **`check_platform_headway(station_code)`**: Platform occupancy, headway buffers, and dwell requirements.
5. **`get_prediction_details(train_id)`**: Machine learning confidence score, CRPS score, and quantile boundaries.
6. **`get_feature_importance(train_id)`**: Top factor weights impacting delay (e.g. prior station delay, visibility).
7. **`get_propagation_graph(train_id)`**: Downstream delay cascade graph across the railway network.
8. **`get_event_log(start_time, end_time)`**: Chronological operations log for timeline reconstruction.
9. **`get_history(train_id)`**: Historical section traversal times and past delay patterns.
10. **`get_network_topology()`**: Network nodes, track sections, speed limits, and signal blocks.
11. **`search_rulebook(query)`**: BM25 retrieval over 20 Indian Railways Operating Rules returning stable rule IDs.
12. **`run_counterfactual(train_id, action, params)`**: Simulates "what-if" actions (`HOLD`, `PRIORITIZE`, `SPEED_RESTRICT`) and returns net passenger-minutes saved without modifying live state.

## 🎬 3-Minute Hackathon Demo Script

Follow this script to demonstrate the complete intelligent dispatch lifecycle to judges:

### Step 1: Intelligent Conflict Triage & Analysis (1 min)
1. Launch the platform and open **Dispatcher Copilot** in the left sidebar.
2. Select target train **12951 (Mumbai Rajdhani Express)** and active alert at **Mathura Junction (MTJ)**.
3. Click **"Analyze with Gemma 4"**.
4. Observe the live **`AgentTrace` accordion**:
   - Step 1: `query_conflicts(junction_id="MTJ")` returns converging freight and passenger services.
   - Step 2: `run_counterfactual(train_id="12951", action="HOLD", params={"duration_minutes": 15})`.
   - Step 3: `check_platform_headway(station_code="MTJ")` checks platform availability.
   - Step 4: `search_rulebook(query="precedence rajdhani freight loop line")` retrieves rule **`PREC-01`**.

### Step 2: Human-in-the-Loop Order Sign-Off (45 sec)
1. Review the generated recommendation card:
   - **Recommended Action**: `HOLD` on freight service `09002` to clear corridor path for Rajdhani `12951`.
   - **Net Impact**: `+1200.0` passenger-minutes saved.
   - **Rule Citations**: `PREC-01` (Superfast & Rajdhani Precedence Over Freight).
2. Click **"Edit Draft"** to adjust controller remarks, then click **"Approve Order"**.
3. View the immediate entry in the **Controller Decision Audit Log** with Controller ID and timestamp.

### Step 3: Multi-Turn Natural Language Control Chat (45 sec)
1. Switch to **Control Chat** in the sidebar.
2. Click the quick prompt: *"What happens if I hold train 12951 at Mathura (MTJ) for 15 minutes?"*
3. Notice that Gemma 4 calls `run_counterfactual` live and reports the exact simulated delay impact without hallucinating numbers.

### Step 4: Multimodal Vision & Bilingual Passenger Advisories (30 sec)
1. In **Dispatcher Copilot**, click **"Upload Display / Diagram"** to open the Visual Analyst.
2. Upload a screenshot of a station status display or signal diagram; observe Gemma 4 extract trains, delays, and platforms with the mandatory **"Needs Controller Confirmation"** badge.
3. Switch to **Passenger Advisory**, select train `12951`, and click **"Generate Passenger Advisory"**.
4. Toggle between **English** and **हिंदी (Devanagari)** announcements, and click **"Play PA Announcement"** for real-time speech synthesis broadcast.

### 🔑 Step 1: Configure Environment Variables

1. Get a free API key from [Google AI Studio](https://aistudio.google.com/).
2. Create or update `backend/.env` with your API key:
   ```env
   GEMINI_API_KEY="your-google-ai-studio-api-key-here"
   GEMMA_BACKEND="gemini"
   DATABASE_URL="sqlite:///./railway_eta.db"
   ```
   *(Note: `backend/.env` is strictly gitignored to ensure credentials are never pushed).*

---

### ⚡ Step 2: One-Click Startup (Windows)

On Windows, launch both the backend server and frontend console simultaneously with:

```powershell
.\start_app.ps1
```

- **Backend API**: `http://localhost:8000` (Interactive Swagger Docs at `http://localhost:8000/docs`)
- **Frontend Operations Console**: `http://localhost:3000`

---

### 🛠️ Step 3: Manual Startup

#### A. Backend Setup (FastAPI & ML Engine)

1. Open a terminal and navigate to the `backend` folder:
   ```bash
   cd backend
   ```

2. Create and activate a Python virtual environment:
   - **Windows (PowerShell)**:
     ```powershell
     python -m venv venv
     .\venv\Scripts\activate
     ```
   - **Linux / macOS**:
     ```bash
     python3 -m venv venv
     source venv/bin/activate
     ```

3. Install backend dependencies:
   ```bash
   pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. Initialize database tables (creates SQLite tables for decisions, runs, and cache):
   ```bash
   python -c "from app.db.init_db import init_db; init_db()"
   ```

5. Start the backend server:
   ```bash
   python run.py
   ```
   The server will start on `http://127.0.0.1:8000`.

#### B. Frontend Setup (React + TypeScript + Vite)

1. Open a second terminal and navigate to `frontend`:
   ```bash
   cd frontend
   ```

2. Install Node dependencies:
   ```bash
   npm install
   ```

3. Start the Vite development server:
   ```bash
   npm run dev
   ```
   The console will launch at `http://localhost:3000`.

## 🔧 Troubleshooting Guide

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| **PowerShell script execution disabled** | Windows security policy blocks `.ps1` scripts | Run `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process` |
| **Port 8000 or 3000 in use** | A previous instance is still running | **Windows**: `npx kill-port 8000 3000` or stop Python/Node in Task Manager<br>**Linux/Mac**: `lsof -ti:8000,3000 \| xargs kill -9` |
| **`sqlite3.OperationalError: no such table`** | Database schema not initialized | Run `python -c "from app.db.init_db import init_db; init_db()"` in `backend/` |
| **500/503 from Gemini Free-Tier** | Temporary API quota limit or network blip | The system automatically retries and falls back to deterministic local engines (`"source": "fallback"`). No action needed. |
| **Vite build error** | Outdated Node modules | In `frontend/`, run `npm cache clean --force` followed by `npm install` |

## 🛡️ Security, Safety, and Compliance

1. **Zero Autonomous Actuation**: Gemma 4 is strictly an advisory engine. All operating directives require controller digital sign-off.
2. **Deterministic Fallback**: If the Gemini API experiences network disruption, the harness seamlessly falls back to local heuristic engines with the `"source": "fallback"` flag.
3. **Prompt-Injection Immunity**: Free-text logs, image inputs, and controller queries are treated as pure data payloads, isolated from instructions.
4. **Audit Trail**: Every inference, prompt token, tool invocation, and decision is stored in the `agent_runs` and `agent_decisions` SQLite tables for post-incident review.
